# Troubleshooting

Start with the self-test: run `Aurelia_Finance_Lab.exe --selftest`. It checks the libraries, the data folder, your
database (read-only), the calculations, the Excel grader and every page, and writes a report to
`%APPDATA%\AureliaFinanceLab\diagnostics\`. The report names the failing check.

## Starting the app

| Symptom | Cause and fix |
|---|---|
| "Windows protected your PC" | The executable is not code-signed. Choose *More info → Run anyway*, or ask your IT team to sign it. |
| Antivirus quarantines the exe | A false positive common to PyInstaller apps. Restore it and add an exception, or build it yourself with `build_windows.bat`. |
| Nothing happens / error about the Qt platform plugin "windows" | The folder is incomplete. Unzip the **whole** `Aurelia_Finance_Lab` folder and run the exe from inside it; do not move the exe out of the folder. |
| "Could not open the local database" | The data folder is not writable or the database is damaged. Check you can create files in `%APPDATA%\AureliaFinanceLab`. Rename `aurelia.db` to keep it and start again, or restore a backup. You can also run with `--data-dir D:\SomeFolder`. |
| "Data integrity" warning at start | A database check failed. Use **Settings → Restore from backup**, or the safety copies `aurelia.pre-restore-*.db` / `aurelia.pre-reset-*.db` in the data folder. |
| Blurry or tiny text | Windows display scaling. Right-click the exe → Properties → Compatibility → *Change high DPI settings* → *Override … System (Enhanced)*. |
| Slow first start | Windows Defender scans the application files the first time they run; later starts are faster. |

## Calculations and pages

| Symptom | Cause and fix |
|---|---|
| A value I typed was refused | It is outside the driver's allowed range or the wrong type; the message names the range. The previous value is kept. |
| Statements page shows a failed integrity check | Usually an extreme scenario (for example more rooms out of order than exist). Read the warning, change the driver back, or press **Revert**. If a reference scenario fails, run the self-test and report it. |
| "Funding gap" warning | Cash would go below zero after the revolver limit. The plan is not financeable as configured: raise the revolver limit or minimum cash buffer, or change the plan. |
| A page shows "This page failed to load" | A programming error; the page shows the technical details. Run the self-test and keep the report. The rest of the app keeps working. |
| Monte Carlo results differ from a colleague's | Different seed, iteration count, distributions or scenario. All four are shown on screen; with the same inputs the results are identical. |
| I lost changes | Changes are auto-saved as a draft and restored at the next start. *Save* writes them into a scenario. Checkpoints and the audit trail (Scenario Lab) show the history. |

## Excel Lab

| Symptom | Cause and fix |
|---|---|
| "This does not look like an Aurelia training workbook" | Grade a file generated by the Excel Lab, with its sheet names unchanged. Your own workbooks cannot be graded. |
| "Could not open the workbook" or "Only .xlsx / .xlsm workbooks can be graded" | The file is locked in Excel, password-protected, damaged or not an .xlsx/.xlsm. Close it in Excel and try again. |
| A correct answer is marked wrong | Check the cell address in the task list; answers must be in the yellow cells. Values typed without a formula earn only the value part (70%). |
| "cell(s) had saved values that differ from recalculation" | Excel's stored result and the app's calculator disagree, usually because the workbook was not recalculated before saving. Press F9 in Excel, save, and grade again. |
| A cell is flagged "unsupported function" | The app's calculator does not implement that function. The cell is graded on the value Excel saved. If the file was saved by a program that stores no results (some online editors), that cell cannot be checked; open and save it in desktop Excel. |
| My original file changed | It cannot: the app only reads a copy in `%APPDATA%\AureliaFinanceLab\graded\`. Generated workbooks never overwrite existing files; a numbered copy is created. |

## Reports and exports

| Symptom | Cause and fix |
|---|---|
| PDF export fails | The target folder is not writable or the file is open in a PDF viewer. Close it or choose another name. |
| Excel export fails | The file is open in Excel. Close it or choose another name. |
| Report says actions need "assign a name" | Suggested actions have no owner yet. Add owners and due dates in **FP&A → Action plans** and preview again. |

## Data

* **Back up** regularly with Settings → *Back up…*; the backup is a single `.db` file.
* **Restore** validates the backup first and keeps a safety copy of your current data.
* **Reset** requires typing `RESET` and also keeps a safety copy.
* **Moving to another PC**: back up, copy the `.db` file, restore on the new PC.

## Building

See [BUILD_WINDOWS.md](BUILD_WINDOWS.md). Common problems:

| Message | Fix |
|---|---|
| "Python 3.12 not found" / "Found Python 3.x" | Install 64-bit Python 3.12, or pass `-Python <path>` to the build script. |
| pip cannot download packages | Check internet access; behind a proxy, `set HTTPS_PROXY=http://proxy:port` before running the script. |
| "tests failed" | Read `build\test-output.txt`. Do not ship a build whose tests fail. |
| "the built executable's self-test failed" | Read `build\exe-selftest-report.txt`; it names the failing check. A missing module usually means the spec needs a hidden import. |
| PowerShell refuses to run the script | Use `build_windows.bat`, which runs it with `-ExecutionPolicy Bypass` for this script only. |
